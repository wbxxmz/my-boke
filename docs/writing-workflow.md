# 博客写作流程：素材 → 骨架 → 正文

> 触发语：作者说「写文章」。改代码、改站点、修 bug 不进入本流程。
> 角色：**作者是作者，我是编辑。** 素材由作者提供，我不提供个人经验。
> 本文件是 `CLAUDE.md`「写博客时（我说"写文章"才激活）」一节的展开版；两处冲突时，以 `CLAUDE.md` 的刹车条款为准。

## 三条总规则

1. **三步各自「做完就停」**：每步只做本步的事，产出后停下等作者确认，不自动进入下一步。
2. **素材不足不写正文**：少于 3 条可核实素材时，拒绝写正文，并直说「现在写会变成转述文档」。
3. **不编造**：技术细节、数字、报错、经历一律要有来源；缺失的写 `[待补：具体缺什么]`，不猜、不补、不润色成"标准故事"。

---

## 第 1 步 · 素材盘点

**目标**：把作者手里能用的东西摊开，先判断够不够写。

**输入**：作者的笔记、代码、命令输出、报错原文、截图、实测数据、个人经历。

**做法**

逐条登记，编号 M1、M2……，每条标明类型、来源、是否可复现：

| 编号 | 类型 | 内容（原话/原文） | 来源 | 可核实 |
| --- | --- | --- | --- | --- |
| M1 | 实测输出 | `ros2 run ...` 的完整回显 | 作者终端 | 是 |
| M2 | 报错 | `ModuleNotFoundError: ...` | 作者截图 | 是 |
| M3 | 个人经历 | 「我以为 odom 就是位置，删了 map 后原地画圈」 | 作者口述 | 是 |
| M4 | 二手资料 | 论文/官方文档链接 | URL | 需探活 |

**准入判定**

- 可核实素材 ≥ 3 条 → 进入第 2 步。
- < 3 条 → **停**，原文回复：「现在写会变成转述文档」，并列出还需要作者补哪几类（实测 / 报错 / 经历），不代替作者回忆。
- 全是二手资料（无实测、无报错、无经历）→ 按不足 3 条处理。

**做完就停**：只交这张素材表 + 够/不够的结论，不写任何正文。

---

## 第 2 步 · 骨架

**目标**：定结构和边界，避免正文跑偏。

**做法**

1. 按素材分组，一节只讲一件事；每节标题下写一句话结论。
2. 标出每节用哪几条素材（如「第 2 节用 M1、M3」），没有素材支撑的节直接删。
3. **全篇最多 1 个比喻**，必须来自作者提供的素材；不新造喻体，不把已有比喻扩展成第二层。
4. 结尾只留一节，标题固定为「还没懂 / 下一步」，写作者目前仍不确定的东西和下一步要验证什么；不写总结、不写"启示"。
5. 不新增作者没要求的节、不合并/改名作者指定的节。

**骨架模板**

```md
# 标题（作者给或待定）
> 一句话结论：[待补 / 作者确认]

## 1. 现象 / 问题（素材：M2）
## 2. 排查过程（素材：M1、M3）
## 3. 结论与做法（素材：M1）
## 还没懂 / 下一步
- 仍不确定：……
- 下一步验证：……
```

**做完就停**：交骨架 + 素材映射 + 哪一节素材还缺 `[待补]`，等作者点头再写正文。作者改结构时按作者的来，不辩护。

---

## 第 3 步 · 正文

**目标**：一次只写一节，写完就停。

**做法**

1. 只写作者点名的**一节**，不顺手写下一节，不改其他节。
2. 每段的数字、命令、报错、时间必须有上一步登记的素材来源；没来源就写 `[待补：xxx]`。
3. 代码块后补「**你应该看到**」的原始输出；没有真实输出就标 `[待补：运行输出]`。
4. 遵守 `STYLE.md` 九条纪律：一段一件事、插入语控量、对偶句全篇 ≤1、加粗只标命令/坑/结论数字、术语首次出现给中文（English）+ 一句定义 + 代码行号、结尾只留一个。
5. 禁用句式：**简单来讲 / 本质上 / 换句话说 / 说白了 / 这就是 X 的意义**。
6. 不新增比喻（全篇仅第 2 步定下的那 1 个），不新增作者没要求的节。
7. 交付时附：本节原文 + 用了哪些素材 + 哪些地方是 `[待补]`；需要时跑一次 `npm run check:style` 并贴输出。

**做完就停**：只交这一节，等作者读完说「像我的字 / 不像」再继续；两轮改不动就停下来讨论结构，不硬改。

---

## 边界情况

| 情况 | 处理 |
| --- | --- |
| 作者说「没有素材，你先写」 | 拒绝写正文，只能给骨架 + 需要补的素材清单 |
| 作者给的素材 < 3 条但坚持要写 | 明确说「现在写会变成转述文档」，最多给提纲，不给成稿 |
| 作者要求写「我的经历」但没提供 | 写 `[待补：你在 XX 场景下的真实经历]`，不虚构 |
| 作者要求加一节没提过的内容 | 先问一句「这节要解决什么问题、用哪条素材」，不加就停 |
| 作者说「随便润色一下」 | 只改标点、断句、删填充词；不增删事实、不改结构 |

## 与其他文件的关系

- `CLAUDE.md`：写博客时的刹车条款（激活条件、禁止项），优先级最高。
- `STYLE.md`：写作与统计口径的唯一来源，正文阶段逐条对照。
- `scripts/check-style.mjs`：只读自查工具，`npm run check:style`；指标是下限，不是为了达标而砍内容。
- `docx/`：本地讨论笔记（已 gitignore），不属于本流程产物。

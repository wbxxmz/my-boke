> 我是一名正在学习 ROS2 的开发者，笔记本是 RTX 4070（8GB 显存）。这段时间我把"怎么用上大模型"这件事从里到外琢磨了一遍：开源闭源、本地部署、云 API……这篇文章记录我的理解和选择思路，写给和我一样从零开始琢磨这件事的人。

## 一、先搞懂最基础的问题：开源和闭源到底差在哪

一开始我总被"开源模型""闭源模型"这两个词绕晕，后来用餐厅类比一下子就通了：

- **开源模型**：餐厅把菜谱公开了。你不仅能照着菜谱自己做菜（本地部署），还能改良配方（微调），甚至开自己的餐厅（商业化）。代表选手：Meta 的 Llama、阿里的 Qwen（通义千问）、DeepSeek。
- **闭源模型**：餐厅只卖做好的菜，秘方锁在后厨。你只能点菜（API 调用），菜好不好吃全看厨师，但你可以换一家吃。代表选手：GPT-4、Claude。

（补个小注：严格说业界管这些叫"开放权重"（open-weight）——菜谱确实给你了，但能不能开餐厅、怎么开，各家合同不一样。比如 Llama 的 license 就有不少限制，真想商用得先读合同。餐厅类比帮理解没问题，真要用起来，license 是另一门课。）

两者的核心区别总结成一张表：

| 对比项 | 开源模型 | 闭源模型 |
|--------|---------|---------|
| 模型权重 | 公开可下载 | 完全保密 |
| 使用方式 | 可本地部署、可 API | 只能 API 调用 |
| 能否修改 | 可以微调定制 | 不行 |
| 数据隐私 | 本地部署数据不出门 | 数据要发到对方服务器 |
| 费用 | 本地跑免费，API 按量付费 | 只能按量付费 |

效果上呢？斯坦福每年的 AI Index 报告给过一组数字：2024 年初，最强的闭源模型在 Chatbot Arena 榜单上领先开源模型 8 个百分点；2025 年初缩到 1.7%；2026 年初又回到 3.3%。所以更准确的说法是：**开源确实追上来了，但这个差距近几年一直在收窄和反弹之间来回横跳**，谁也没把谁甩掉。中文能力上国产模型确实有主场优势；长文本则要留个心眼——"上下文窗口开得长"和"真的能读懂长文"是两回事，窗口长度是广告，理解深度是本事。

还有个容易混淆的点：**7B 不是上下文长度，是参数量**——70 亿个参数。参数量大致决定模型的"脑容量"，数字越大一般越聪明，但也越吃硬件。

## 二、我的本地部署初体验：4070 能跑什么

既然开源模型能下载，我第一反应就是：能不能白嫖，在自己电脑上无限用？

答案是可以，但有条件。我用 Ollama 做本地部署，8GB 显存的 4070 笔记本实际体验如下：

- **7B 模型**：4bit 量化后流畅运行，日常问答、简单代码没问题
- **14B 模型**：勉强能跑，比较吃力
- **更大的模型**：显存不够，跑不动

适合本地的模型：Qwen2.5-7B、Qwen2.5-Coder-7B（写代码）、DeepSeek-Coder-V2-Lite 等。配上 Open WebUI 还能获得类似 ChatGPT 的网页界面。

这里得给"4bit 量化"补个小提醒：论文里的结论是，4bit 在日常问答上基本无损，但**复杂推理和长文本会有能感知的退化**——有研究测到低比特量化在数学推理任务上最多掉了 30 多个百分点的准确率，长文本任务在 4bit 下也有明显衰减。一句话：量化是为了塞进显存做的妥协，日常用没事，重活别指望。

本地部署的真实优缺点：

**优点**：免费无限用、数据完全不出门、断网也能用。

**缺点**：硬件门槛高（想跑更强的模型得上万元甚至几万元的显卡）、能力上限低（7B 模型的聪明程度有限）、显存不够时速度暴跌（权重溢出到内存，慢得没法用）。

最让我失望的是实际能力：我试着让本地的 7B 模型帮我做复杂点的文件操作，比如整理文件夹、改游戏配置文件，结果发现它的**工具调用能力很弱**，常识也不足，让它乱动系统文件甚至有风险。简单任务它能干，复杂任务基本指望不上。

后来查文献发现这不是我的错觉：UC Berkeley 的 TinyAgent 研究里，开箱即用的小模型做函数调用错误百出——选错函数、编造不存在的函数名、参数依赖搞乱，跟我的体验一模一样。但有意思的是，**问题不在于"小"，而在于"通用"**：同一类研究里，用高质量数据专门微调过的 7B 小模型，函数调用能力反而超过了 GPT-4-Turbo；另一篇 Hammer 论文微调的 7B 也拿到了类似的成绩。也就是说，开箱即用的小模型指望不上，但专门调教过的小模型能打——只是"下载就能用"和"自己调教"是两回事，后者已经是另一个量级的折腾了。

## 三、用不起本地，那就看看云 API：硅基流动是什么

本地部署碰壁后，我把目光转向了云 API，然后注意到了硅基流动（SiliconFlow）这家公司。

**硅基流动是国内一家做 AI 基础设施的创业公司，说直白点，就是专门"卖 token"的**——你按用量付费，它负责把模型跑在它的服务器上。它不和字节、阿里这些巨头比谁的模型更强，而是做标准化的推理服务，聚合了各家开源模型，你想用哪个调哪个。

这和火山方舟（字节跳动）的定位很不一样：

- **火山方舟**：大厂背景，主打自家豆包系列模型
- **硅基流动**：创业公司，聚合多家开源模型，像模型的"超市"

硅基流动的价格明显便宜，原因我个人的理解有四个（以下是我的推断，不是官方说法）：

1. **不做训练，只做推理**：省下了天价的模型训练成本，成本结构更轻
2. **自研推理引擎**：运行效率高，同样硬件能服务更多请求
3. **规模效应**：用户多了，摊薄成本
4. **市场补贴**：创业公司抢市场阶段，贴钱换用户

有个细节值得注意：硅基流动**不能调用 GPT 这类国外闭源模型**（人家不开放），但可以调用 Llama、Gemma 等国外开源模型——开源模型权重是公开的，谁都可以部署来卖。这也是开源生态的好处：模型一旦开源，全世界的服务商都能帮你跑。

## 四、三种方式摆在一起，怎么选

把所有选项摆上桌，其实是三条路：

| | 本地部署（Ollama） | 云 API 聚合平台（硅基流动） | 官方 API（如 GPT） |
|---|---|---|---|
| 费用 | 免费但硬件贵 | 便宜，按量付费 | 最贵，按量付费 |
| 模型能力 | 限于硬件，7B 级别 | 可用各家开源大模型 | 最强闭源模型 |
| 速度 | 单人体验不慢，弱在并发 | 快，但首字延迟看网络 | 快，但首字延迟看网络 |
| 隐私 | 数据不出门 | 数据上云 | 数据上云（还要出境） |
| 适合场景 | 学习、隐私敏感、离线 | 日常开发、性价比优先 | 追求最强效果 |

有个反直觉的点值得单独说：**"云 API 快"其实不绝对**。云端推理的首字延迟通常在几十到几百毫秒，还得看网络脸色；而本地跑 7B 4bit 模型，消费级显卡能跑到每秒几十个 token，单人用起来往往不比云端大模型慢。真正的区别是：本地是"自家灶台"，点火就炒，但一次只能伺候你一个；云端是"大后厨"，能同时出几百份菜，但你的菜要经过配送。所以需要扛高并发、多用户的服务必须上云，个人单机使用，本地速度并不吃亏。

我的结论可能有点反直觉：**对大多数普通用户来说，与其在自己电脑上折腾本地部署，不如直接用付费 API**。

空口说"划算"没劲，算笔账：像我这样的个人开发者，就算天天写代码、查资料、改文档，一个月的用量大概也就几十万 token。聚合平台上跑开源模型，价格量级是每百万 token 一两块钱（各家不同），算下来**一个月一块钱上下**；就算经常上更强的模型，一个月也就几块到几十块。而"本地部署省下的 token 钱"，省的就是这几块钱；付出的硬件成本却是几千块的显卡（还得算电费）。**对个人用户来说，token 钱小到可以忽略，硬件钱才是大头**。本地部署的价值从来不在省钱，而在隐私、离线和学习原理——除非你有这些硬性需求，否则不值得为"免费"两个字折腾。

选完"哪条路"之后，我还从论文里学到一个更聪明的玩法。斯坦福有个叫 FrugalGPT 的研究：**简单的问题先问便宜的小模型，用一个打分器判断答案行不行，不行再升级到贵的模型，最后才动用最强模型**。靠这套"级联"打法，他们把成本砍掉了最多 98%，效果还能持平 GPT-4。翻译成人话：不是"选一条路走到黑"，而是"分层用"——小问题便宜模型解决，难题再上强模型。落到我个人身上，其实已经在这么干了，只是之前没意识到：日常写代码、写文档用云端的强模型，本地部署留着学习原理、跑些不在乎质量的小活。

## 写在最后

这一圈了解下来，我最大的感受是：**国内 AI 服务的分工已经很清晰了**——有人负责练模型（DeepSeek、阿里、字节），有人负责把模型便宜地跑起来（硅基流动这类推理服务商），有人负责把模型包进产品（各种 AI 应用）。作为用户，我们其实站在一个挺舒服的位置：开源生态让价格打了下来，竞争让服务越来越好，要做的只是根据自己的钱包和需求，把几条路搭配着用。

如果你也是刚入门的开发者，我的建议是：先把开源闭源的概念搞清楚（餐厅类比真的好用），然后花一点点钱试试云 API 的效果，最后有闲心再用 Ollama 折腾本地部署。这个顺序，时间和金钱的成本都最低。
